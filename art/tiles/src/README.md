给美术（甄塑之）的交付规范。构建脚本 `art/tools/build_tiles.gd` 严格按此读取。

  TIL_<T>_BASE_03.png          底块变体 3「灵芝点」     ← 后续轮次

  TIL_<T>_BAND_E_01.png
  TIL_<T>_BAND_S_01.png

  TIL_<T>_CORNER_NE_01.png     角件：右上 / SE 右下 / SW 左下 / NW 左上
  TIL_<T>_CORNER_SE_01.png

  TIL_WATER_BASE_03.png        水面波动相位 3

`<T>` = `GRASS` / `FOREST` / `ROCK` / `FIELD` / `MARSH` / `WATER`
（**水面是第 6 套，不在第 5 个之内**）

### 变体怎么算（避免笛卡尔积爆炸）

| 件 | 变体数 | 作用范围 | 产出张数 |
|---|---|---|---|
| BASE | 3 | **只作用于 mask=0**（内部格，占屏 90%+） | 3 |
| BAND | 4（相位偏移） | 其余 15 个掩码，各 4 个 | 60 |
| CORNER | 1 | 不参与变体 | — |
| **每地形合计** | | | **63 张**（6 地形 = 378 张） |

⚠️ **带边格一律只用 `BASE_01`** —— 边格本身已有边带变化，再乘 base 变体组合数会失控。
⚠️ 同一掩码的**四条边用同一个相位号**（不做每边独立，否则 4⁴ 爆炸）。

### ⭐ 边带 4 个相位变体：**脚本能自动生成，你不必手画**

`--phase=4` 会由 1 张母版沿边**循环平移** 0 / 64 / 128 / 192 源px 生成 4 个变体
（笔法、光向、墨线完全一致，只有纹样相位不同 —— 就是你说的「相位偏移法」）。
⇒ 若采用，**你的 BAND 交付量从 16 件降到 4 件/地形**（母版 8 件 → 全 6 套 24 件）。
⇒ 前提：**母版必须沿边方向无缝**（周期 256 源px），脚本会查，不无缝会点名报 warning。

#### ⚠️ 相位母版的两条硬约束（2026 定，违反会让 4 个变体全废）

1. **顺序**：脚本内是 `母版 256 → 循环平移 → 逐件 bleed → 合成 256 → 一次性降采样`。
   ⚠️ **不是**「先降采样到 64 再平移」—— 那样纹样与墨线已被合并过一次，再平移会让
   「墨线粗细变化的位置」与纹样错位，且循环性已被重采样破坏。
   ⇒ 平移出来的是**完整的一张 256 母版**，后续与手绘件走完全相同的管线。
2. **主尺度 80~120 源px，不得含 64 / 128 源px 的周期子结构**。
   因为平移间距**固定 64**；若母版本身有 64 或 128 周期，平移后的分段会与母版雷同
   ⇒ **4 个变体退化成 2 个，等于没做变体**。
   ✅ 脚本会查（沿边平移 64 / 128 的差异 vs 互质位移 37 的差异，比值 <0.35 即点名报 warning），比肉眼可靠。

#### 将来加第二张母版（本轮不用，路没堵死）
索引语义是**母版槽位**：约定第二张用 `_05`（第三张 `_09`，间隔 4），
脚本应把每个已存在的索引当母版、各自再展开 `_06.._08`。本轮不实现。

## 每件的规矩

| 件 | 尺寸 | alpha | 内容 |
|---|---|---|---|
| `BASE_01` | 256×256 | **必须完全不透明**（不允许任何透明像素，否则会透出背景） | 地表底块，严格 wrap 无缝 |
| `BAND_*` | 256×256 | 整张透明图，**只在该边一侧画内容** | 边带：外沿墨线/暗边收口 + 向内约 64 源px 渐变回本地形底色 |
| `CORNER_*` | 256×256 | 整张透明图，**只在对应角画内容** | 角件 |

## 合成规则（脚本实现，不要按别的顺序画）

```
底块 → 边带（掩码包含的边）→ 角件（两条相邻边都在才叠该角，角件在最上层）
```

掩码位：`bit0=N(上) bit1=E(右) bit2=S(下) bit3=W(左)`，与 `Game._auto_tile()` 一致。
16 个掩码 → 输出 `TIL_<T>_SIDES_<NONE|N|NE|NES|NESW|…>.png`，落 `art/tiles/built/`。

## ⚠️ 硬规矩（2026 定稿，共 8 条）

1. **四边各留 4px 安全环** —— **只对 BASE（或任何含点状元素的件）生效**。
   环内不放独立元素端点（灵光点、纹样起止、描边转折），纹样一律 wrap 跨边接上。
   ⇒ **BAND / CORNER 不用留环**（见第 6 条）：它们按第 3 条不放点状元素，环要防的东西不存在，
   且脚本的 bleed 是 **clamp（复制最近有效内容）**，留环反而会把 6px 墨线撑成 10px。
   ⇒ **紧贴外缘 0px 画即可**（2026 裁定，读法 A）。
2. **不要手工做 bleed / 外扩**：脚本自动做，**不污染 256 源图**。
   - BASE（不透明 / 无缝）→ **wrap bleed**：外扩区填**对边**内容（x=0 的外面是 x=255）
   - BAND / CORNER（带 alpha）→ **clamp bleed**：外扩区填**最近的有效内容**
   ⚠️ 两套不能共用，脚本按有无 alpha 自动选。
3. **底块必须严格 wrap-around 无缝** —— 这一条比看起来更硬，见下方「 bleed 实测 」。
4. **BAND 不画角区（与 CORNER 区域互斥）**：每条边带只画**沿边方向的中段**，
   **两端各 64 源px 完全不画**，端头只由 CORNER 填。
   *因果*：两件都是带 alpha 的半透明件，若 BAND 也覆盖端头 → **叠加两次 = 双重压暗 = 角上出现一块比别处深的补丁**。
   ✅ 脚本双保险：端头有内容会 `push_warning` 点名**且**强制清空（宁可要显性的露空，不要隐性的深补丁）。
5. **BAND 沿边方向也必须无缝**（周期 256 源px）：不只垂直边界方向。
   *因果*：① 一条长直边界上每 64 屏幕 px 断一次，比重复本身更显眼；
   ② 相位偏移变体（沿边循环平移）**全靠这个周期性才成立**，母版不周期则变体全废。
   ✅ 脚本会查（N/S 查左右列、E/W 查上下行，差 >0.08 点名报 warning）。
6. **BAND / CORNER 内不放任何点状元素**（灵光点、灵芝点、纹样端点）—— 只放连续带、渐变、墨线。
   点状元素在沿边方向会被相邻格切断。点状元素归 BASE 和 deco。
7. **BAND 内侧渐变必须渐变回 `BASE_01` 的颜色**，不是 BASE_02/03 ——
   因为带边格固定用 BASE_01（变体规则②），对不上会出现一圈色差。
8. **CORNER 画成双向可读**（45° 圆角墨线 + 柔和 AO，不带方向性暗示）—— 脚本不分内外角。
   另：**四条边各画，不可旋转复用**（全场单一光向左上 45°，N/E/S/W 受光背光本就不同）。

## 另两张图（不走本目录的 4× 降采样管线）

### 灵脉 / 地势 overlay（大周期低频层）
- 母版 **1792 × 2048** 源px，**必须双向 wrap 无缝**（横纵周期不同，所以是长方形）
- 逻辑周期 **横 896 × 纵 1024**（= 母版 ÷ 2，即 1:1 像素密度）；3584/896 = 4、3072/1024 = 3，**双向整除，边缘无缝**
- 周期均 > 一屏宽（683 逻辑 px）⇒ 一屏内看不到第二次重复
- 明度浮动 **±5% 封顶**；只画大块低频渐变，**不塞细节**（1:1 密度下细节会比地块锐利，反而糊掉「地面后退」的层级差）

## 🔬 bleed 实测记录（2026，甄塑之提出 → 实测确认 → 已修）

**结论：底块也需要 bleed。「底块严格无缝就不需要 bleed」这句话是错的。**

| 实验 | 结果 |
|---|---|
| 真·无缝底块（6px 墨线横跨左右边界）单独降采样，**无 bleed** | 左列 **0.035**（源墨线 0.071、底块 0.447）⇒ **边缘被额外拉暗约一半** |
| 同上，加 wrap bleed | 左列 **0.051** ⇒ 恢复到墨线本色 |

*机理*：4× 降采样时最外侧目标像素的 Lanczos 核有一半落在画布外，引擎按 **0（黑）** 采样，
**不是** clamp-to-edge。核支撑 ≈ 12 源px，一半 ≈ 6 ⇒ **bleed N 取 8**（他建议 ≥6，8 更稳）。

⚠️ 两个坑（都实测过）：
- **均匀区域看不出这个 bug**（采到 0 后权重也被归一化，实测四外圈-内部 = -0.0044，在噪声内）
  ⇒ 只有**边缘有内容**的件才露馅 —— 最难发现的一类缺陷。
- **bleed 的取源必须是「对边」不是「对侧中心」**：用 +S/2 会取到 tile 中心，实测把跨边界的墨线
  洗成纯底色（0.447）。无缝件的正确延续是 x=255，不是 x=128。

**两种实现**：默认 **crop**（外扩画布 → 降采样 → 裁回 64，缩放比 (256+2N)/64 = 4.0625，
环绕内容总是真实邻格内容）；`--bleedmode=wrap` 为原地环绕（缩放比精确 4，但环绕内容可能与
实际邻格不符）。**按 crop 走，两者实测指标一致。**

## 源图规范（按 4× 降采样换算，屏幕一格 = 64px）

- 墨线：源图 **5~6px** → 屏幕约 1.4px
- 最小可辨元素：源图 **≥16px** → 屏幕 4px（纹样「大而少」，每块 3~5 个大元素）
- 高光点：直径 **12~16px**，距边界 **≥24px**
- 全场单一光向：**左上 45°**，N/E/S/W 四边各自受光/背光不同，**必须四条各画，不可旋转复用**
- 地表底块**不画外描边**（避免满屏网格），描边只给 deco 与立壁

## 跑构建

产物命名 `TIL_<T>_M<掩码>_V<变体>.png`（如 `TIL_GRASS_M05_V02.png` = 掩码 N+S、相位 2），
另出 `manifest.json` 记录每个文件的 mask / variant，接线 TileSet 时直接读。

```
"C:/Users/Administrator/Desktop/gu_tools/Godot_v4.7.2-stable_win64_console.exe" \
  --headless --path "C:/Users/Administrator/Desktop/yunling" \
  --script res://art/tools/build_tiles.gd -- --phase=4
```

⚠️ 注意：参数要放在 `--` 之后才传给脚本（`--script` 模式下不加 `--` 会被引擎吃掉）。
无参数跑会逐个地形报「无件，跳过」—— 这是正常待料状态，不阻塞。
自检（美术件没到位时）：加 `-- --selfcheck`。
⚠️ 跑完**必须手动 `--import`**，否则 Godot 不重新导入、地形全读 0（项目踩过一次，碎了 12 条断言）。
